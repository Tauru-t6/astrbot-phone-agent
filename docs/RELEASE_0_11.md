# 0.11.0 / App 0.5.0 更新说明

**代码与服务器接口已验证，真实手机的新功能验收待设备连接后完成。** 本文描述行为和验收要求；实际版本、附件和检查结果以发布时记录为准。

## 用户能做什么

| 能力 | 行为与界限 |
| --- | --- |
| 返回任务成果 | 收集 1–10 条页面结果，标题必需；作者、时长和 URL 可见且复核后才返回，缺项为 `null` |
| 收藏带参数任务 | 从已批准/完成任务保存范围；只替换声明的目标与文本参数，复用前再次审批 |
| 复用操作经验 | 显式选择且最终核验完成后保存控件选择器和步骤后条件；无坐标回放、旧快照或旧 grant |
| 接手后继续 | 从当前页面创建新运行和新批准，使用剩余预算；未知结果先确认，成功/取消任务不续跑 |
| Bot 自主日程 | Bot 专用机、时区、静默时段、到期和次数/模型调用额度；离线不补跑、重启不重放 |
| 扫码连接与撤销 | 120 秒一次性码兑换设备专用凭据；面板 JWT 留服务器，可撤销单台设备 |
| 截图/OCR 辅助 | 服务端与任务均须开启；选择语义/OCR 节点，OCR 只点击/返回，画面变化停止 |
| 个人机体验 | 保留简洁首页；区分健康来源、尝试与成功上传、过期/错误信息，增加设备自检 |
| 设置页直达 | 预定义显示/Wi-Fi 设置入口列入批准范围，只用于 Android 设置应用 |

任务仍限制在批准的应用和设备内。支付、发送/发布、登录、删除、安装、权限授予与含糊目标由人工处理。模型调用上限不是金额或 Token 估算。

## 升级与配置

1. 升级主插件与对应 App，保留个人/Bot 独立包名。先用已有连接确认注册和 Shizuku。
2. `enable_ui_tasks`、`enable_task_execute`、`enable_observe_tool` 仍是界面任务基础开关。
3. 按需开启 `enable_task_routines`、`enable_ui_vision` 或 `enable_device_pairing`；默认不新增自主日程、截图或网关。
4. 扫码需网关监听和手机可访问地址，例如 Tailscale `http://100.x.x.x:8766`；上游默认本机 AstrBot 插件路由。公网要求 HTTPS，依赖包含 `requirements.txt` 的 `qrcode`。
5. 新配对设备走专用凭据直连，不取得共享 Relay 密钥；已有 JWT/共享 Token/Relay 继续兼容。传统 Bot Relay 要求 `targeted_polling=true`。
6. 手机按需启用输入法和 UI 免确认；创建日程或截图任务仍须查看完整范围。

完整配置、审批、数据边界见 [界面任务说明](UI_TASKS.md)。Private Companion 和独立关怀桥接不因这些功能自动升级。

## 发布前验收要求

- 结果不能由输入框、模型自述、重复标题、过期节点或错误卡片字段组成；证据变化使任务停止。
- 模板参数不能改设备/包名/权限；经验失配交模型，未知动作不重放；续跑使用新审批并扣除已尝试动作。
- 日程先持久化时刻和预算；同分钟、重启、DST、离线及运行中撤销均有回归覆盖。
- 配对码过期/重用/错用途被拒；设备凭据不能调用面板接口、操作其他设备或继续使用撤销凭据。
- 两个 App 均构建、单测与 lint；Bot 实际 APK 不含健康读取实现或个人通知监听服务。
- 个人机检查健康来源、同步失败/成功、过期与简洁首页；Bot 机验收搜索结果、模板复用、接手和日程。
- 发布包排除凭据、个人数据、临时文件及上游 Private Companion 源码；校验签名、公开下载哈希与源码提交。

上述条目是验收要求，不能理解为本文写成时已全部通过。源码测试和模型模拟不等同于所有设备或 App 版本兼容。
