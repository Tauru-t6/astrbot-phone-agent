# Private Companion 7.1.9 适配与自主决策

版本：Phone Agent 0.9.0；Phone Companion Context 0.3.0；Private Companion 7.1.9。

## 适配方式

7.x 不再提供旧版的 _generate_proactive_message_with_llm。新版桥接按精确插件目录名、启用状态与 companion.product.v1 门面发现宿主，通过独立的手机关怀调度协作，不替换 7.x 内部方法，不读取或写入它的私有 SQLite 表，也不争用外部记忆 Provider 的归属。旧版方法仍存在时保留原桥接路径。

关怀使用 AstrBot 对应私聊的模型、当前对话与人格 API，最多读取 6 条近期纯文本消息，保留原有手机/健康信息开关。不会自动接管 Private Companion 原生主动联系、完整长期记忆或关系权限系统。7.x 如不提供旧版手机授权列表，必须使用 Phone Agent 自己的明确 allowlist，缺少授权时拒绝操作。

长会话仅解析末尾最多 65,536 字符内的完整消息对象，避免超过 2 MB 的历史把整轮关怀阻断。归属不同的会话仍拒绝读取，模型材料最多保留 6 条消息、每条 500 字符。

## 关怀决策

- 只接受结构化 no_action / send_message；兼容 JSON 代码块，拒绝无效 JSON、重复字段及未知动作。
- 近期会话刚有活动时暂不介入。生成后重新核对会话、人格、近期内容、宿主生命周期和授权，变化时丢弃结果。
- no_action 保存上下文指纹和有界复查时间；状态不变时不重复调用模型，保留每天评估/发送额度、静默时段和冷却限制。
- 每个会话/人格范围最多保留 5 条近期关怀，抑制与近期关怀及助手回复高度相似的文字。数据在原有预算文件，不输出到模型/错误日志。
- 保留 preview 不发送、投递明确失败不记成功、结果未知不重发。App care 状态附带桥接模式与安装状态。

新增配置：care_provider_id（空则沿用会话模型）、care_model_timeout_seconds（默认 30）、care_recent_chat_seconds（默认 180）。原有模式、额度和用户列表保留。

POST /app/care/preview 提供鉴权后的无发送预览：只选取白名单中已记录的私聊目标，并要求新鲜设备状态。即使配置为自动发送，本接口也强制只预览；正常扣除一次模型评估预算，不消耗发送额度，不污染自动关怀去重缓存。它不绕过静默、冷却、授权与模型预算限制。

## 手机任务规划

enable_llm_task_planner 默认关闭，本机部署按本次请求开启。task_planner_provider_id 为空则使用对应会话模型；默认单次 20 秒、最多 6 步。只调用一次模型，超时不重试。

模型按目标生成有序步骤，动作与服务端 allowlist 取交集，包名来自应用映射。不猜坐标、不生成 shell、不允许模型签发授权。未知应用或不支持的界面操作返回澄清问题。模型不可用时，仅明确的单步目标可降级为规则规划。

写操作继续走现有审批及逐步核验。计划只创建待批准记录；设备变化、授权关闭、超时和步骤失败不会被报成完成。任务 summary 记录规划来源。失败后不自动重规划或扩大授权；任意 App 的视觉操作循环属于后续能力。
