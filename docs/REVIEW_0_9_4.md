# 0.9.4 审核修复与全面复检

2026-11-11 的 v0.9.3 市场反馈确认未发现恶意行为，但指出 `task_runner.py` 使用内置 `logging`，不符合插件日志规范。本版改为 `from astrbot.api import logger`，不保留运行时 `logging` 回退。测试通过模拟宿主接口独立加载任务模块，并检查所有主插件和桥接运行模块的日志来源。

## 已确认并修复

| 问题 | 修复后行为 |
| --- | --- |
| 任务模块使用内置 logger | 使用 AstrBot 提供的 logger；回归检查覆盖导入和对象身份 |
| 总览页与关怀绕过主功能开关 | 关闭主插件/健康/观察功能后不继续读取或注入对应数据；缓存和异步读取完成后再次检查 |
| 已批准任务沿用启动时的执行策略 | 每一步派发前重新检查开关及动作列表；仅绑定原设备的回滚可以继续恢复应用 |
| ADB 工作流附加字符串未完整转义 | 特殊符号和空格按单个字面参数传入设备 shell |
| 清除成功后在途上传重新保存旧快照 | 清除递增存储代次；已接收的旧上传提交时拒绝并返回 `snapshot_invalidated` |
| 分块传输绕过 64 KiB 限制 | 按实际接收字节限制请求体，并给读取设置超时 |
| 超大 JSON 整数/嵌套结构导致服务端异常 | 返回明确客户端错误；定位数值检查先比较范围再转浮点数 |
| 审计包含任务目标、模型原文或警告正文 | 新日志记录长度、原因及结果元数据，任务历史仍保留用户需要查看的目标 |
| 字符串 `confirmed="false"` 被当成真值 | 按现有布尔解析规则处理后再决定是否需要确认 |

## 复检范围

- 主插件、任务执行器、设备传输、规划器、健康快照、存储、地图诊断和关怀桥接。
- 运行模块日志来源、授权/设备绑定、异步网络调用、异常与取消恢复、凭据重定向保护、数据目录、健康来源/撤权和输入边界。
- WebUI 动态文本转义、请求去重、配置草稿、提醒幂等及真实 API 功能开关。
- 实际运行 ZIP 和桥接 ZIP 的文件清单、Python AST、已知凭据/私钥模式、测试与运行数据排除、压缩包体积和附件校验。

测试使用隔离临时目录及模拟手机，不执行破坏性设备命令或发送聊天消息。源代码审查和回归检查不能保证不存在其它缺陷，也不等同于市场重新审核通过。

运行模块日志检查已加入测试套件，CI 会与功能测试一起执行。包含单模块独立导入测试，避免测试顺序掩盖对宿主 logger 的依赖。Python 3.11 和服务器使用的 Python 3.12 都应执行同一套回归。

本次结果：本地及 Ubuntu Python 3.11/宿主 Python 3.12 的完整测试均为 **444 passed、122 subtests passed**；WebUI **14 passed**。实际宿主验证了任务模块的 logger 与 `astrbot.api.logger` 为同一对象，超大上传返回 HTTP 413，未鉴权访问返回 HTTP 401。主插件 0.9.4 与独立桥接 0.3.2 热重载成功，Private Companion 7.1.14 的扩展门面仍可被桥接发现。

## 升级与边界

主插件升级 0.9.4；使用关怀功能时同时升级独立桥接 0.3.2。App 0.3.28 和 Relay 0.9.1 协议继续兼容。Private Companion 7.1.14 无需因本版再次更新。

快照清除保护覆盖当前进程已接收、尚未提交的上传；它不会把未来重新授权/同步请求永久锁死。网络恢复后应由 App 重新读取再上传。此版本不修改或清除旧审计文件，已有历史中的正文不会自动消失。

独立 `deploy/` 服务和测试宿主桩不作为 AstrBot 运行模块。主发布包继续排除测试和开发目录，完整源码附件单独保留回归测试，便于审查复现。
