# 界面任务、收藏与双设备

本文对应计划发布的插件 **0.11.0** 与 Android App **0.5.0**。这是实现与使用说明，不表示 Release 已发布或所有真机场景均已验收。发布时的实际验证范围见 [0.11 更新说明](RELEASE_0_11.md)。

## 两个 App 怎么选

| | Phone Control | Phone Control Bot |
| --- | --- | --- |
| 用途 | 个人主力机 | Bot 专用手机 |
| Android 包名 | `com.tauru.astrbotphoneagent` | `com.tauru.phonecontrol.bot` |
| 首页 | 连接、个人状态与可选健康摘要，保持简洁 | 发起任务、审批与执行进度 |
| 任务 | 在设置中的自主功能查看、批准或发起 | 首页直接操作，支持批准后的 Bot 日程 |
| 健康 | 可选 Health Connect 来源与摘要同步 | 不含 Health Connect SDK、健康权限、读取或同步实现 |
| 个人通知 | 保留显式授权的通知转发 | 不注册个人通知监听服务 |

两个 APK 有独立安装身份与存储；个人版保留原包名，可覆盖同签名旧版本并保留设置。Bot 版首次安装须单独连接服务器、启动 Shizuku 并授权。角色表示同一部署内的设备分工，不表示任意两名用户可以安全共享面板 JWT。

服务端固定原有 `personal` 主设备，首个 Bot App 登记为 `bot`；额外设备可能为 `unassigned`。当前只启用一个 Bot 角色。任务绑定选定设备与单一应用，离线、用途改变或绑定改变不会转去操作另一台手机。

## 服务器准备

先升级主插件和对应 App，使用 App 后端并配置允许的用户：

```json
{
  "enabled": true,
  "control_backend": "app",
  "allowed_user_ids": "YOUR_ASTRBOT_USER_ID",
  "enable_ui_tasks": true,
  "enable_task_execute": true,
  "enable_observe_tool": true,
  "ui_task_allowed_packages": "tv.danmaku.bili,com.android.chrome,com.android.settings",
  "ui_task_max_steps": 8,
  "ui_task_provider_id": "",
  "enable_task_routines": false,
  "enable_ui_vision": false
}
```

`ui_task_provider_id` 留空时使用任务规划模型或当前会话模型。模型应能遵守 JSON 输出；App 自身不需要配置模型。最多动作数为 1–12，默认 8，打开应用也消耗一步。任务还受总时限与模型调用次数限制。

结果提取、收藏和手动续跑仍走逐次审批。Bot 日程和截图辅助是额外选项，分别受 `enable_task_routines`、`enable_ui_vision` 控制，默认关闭；一次普通任务批准不会自动启用它们。

## 连接手机：扫码或传统配置

### 扫码配对（0.11.0 / App 0.5.0）

配对网关让手机使用独立、可撤销的设备凭据。配置示例中的地址必须替换成你的服务器 Tailscale 地址：

```json
{
  "enable_device_pairing": true,
  "pairing_bind_host": "100.64.0.10",
  "pairing_port": 8766,
  "pairing_public_url": "http://100.64.0.10:8766",
  "pairing_upstream_url": "http://127.0.0.1:6185/api/plug/astrbot_plugin_phone_agent"
}
```

1. 确认手机能访问该 Tailscale 地址，端口未被占用，保存配置并重载插件。
2. 在 AstrBot 面板登录后打开 Phone Control WebUI 的「扫码配对」，选择个人或 Bot 用途并生成二维码。已有设备重配时填对应设备 ID。
3. 在对应 App 的配对入口扫码，或粘贴面板提供的完整配对内容；先核对服务器地址和设备用途，再确认。
4. 二维码 **120 秒有效且只能兑换一次**。过期后重新生成。服务端使用 `requirements.txt` 中的 `qrcode` 生成 SVG；缺少依赖时可先使用完整配对内容。
5. 配对成功后可在面板单独撤销这台设备。撤销会阻止后续设备请求与任务步骤，重新使用须重新配对。

二维码只有短时兑换信息，不包含 Dashboard JWT 或共享 Relay 密钥；上游面板授权保留在服务器。网关仅转发受限的 Phone Control 设备接口。公网地址须使用 HTTPS；HTTP 配对只接受字面本机、LAN 或 Tailscale 地址。网关绑定本机地址时，手机须通过相应代理访问，不能直接连它的 `127.0.0.1`。

**新配对设备当前使用直连命令路径**，不下发部署共享的 Relay 密钥。服务器需要能通过 LAN/Tailscale 到达手机的已注册命令端口，通常为 `8260`。手机能访问网关不等于服务器已能反向控制手机；用设备自检核对两条路径。

### 传统配置与 Relay

已有 Dashboard JWT、手机共享 Token、Relay 地址/Token 配置继续兼容。传统插件地址为 `http://SERVER:6185/api/plug/astrbot_plugin_phone_agent`；Dashboard JWT、`app_shared_token` 与 Relay Token 用途不同，不能互换。凭据过期应重新登录面板更新授权。

传统 Bot Relay 兜底要求正在运行的 Relay 为 **0.10.0 或支持相同协议的后续版本**，且 `/health` 返回 `targeted_polling: true`。仅有 `targeted_tasks: true` 不够。Bot 只领取明确发给本设备的任务，旧版不会回退到无目标队列。升级插件文件后，还须重启实际 Relay 进程；重启 FRP 隧道不等于更新 Relay 服务。

## 执行手机准备

1. 完成连接并确认设备注册、Shizuku 启动与 App 授权。
2. 需要输入文字时，在系统输入法设置手动启用 **Phone Control 输入**；启用不要求永久改成默认键盘。
3. 如需连续执行，在实际执行设备「隐私与自动化」明确打开「读取界面节点」和「操作界面」免确认。默认仍逐条请求本机确认。
4. 保持手机已解锁、屏幕亮起，目标 App 已安装；先手动处理首次登录、验证码与权限弹窗。
5. 任务期间避免同时改动目标页面。节点身份、前台、遮挡或输入连接变化会让任务暂停。

免确认开关表示本机信任已连接服务器发送对应类别的命令，仍需逐次或限额日程审批。手机并不独立验签服务端的任务 grant；它继续校验设备、快照、目标节点和输入连接。

输入时临时切换任务输入法，只输入批准原文，不用共享剪贴板；结束、取消或失败后尝试恢复之前的输入法。如果提示恢复失败，先检查当前页面与键盘，不重放旧输入。

## 提案、结果与完成判定

从 Bot 首页、个人版设置中的自主功能或聊天工具 `phone_ui_task` 发起提案。必须核对：执行设备、单一应用、任务目标、允许输入原文、完成文字、动作上限，以及是否允许返回结果、保存操作经验或使用截图辅助。提案本身不会操作手机。

允许输入最多 5 项、每项最多 200 字符；模型不能另编输入原文。完成条件也须明确，不以命令返回成功、打开应用或搜索框含关键词证明整个目标完成。

### 搜索并返回可核验结果

例如：“在 Bot 手机的 B 站找三个 Kotlin 入门视频，把标题、UP 主和时长给我。”开启结果提取后，审批包含所需字段和数量。协议示例：

```json
{
  "result_spec": {
    "fields": ["title", "author", "duration", "url"],
    "max_items": 3,
    "required_items": 3
  },
  "remember_recipe": false,
  "allow_vision": false
}
```

`title` 必须包含在字段中；数量范围 1–10，`required_items` 不大于 `max_items`。模型只选择当前非输入节点的证据引用，服务端复制页面原文并用新观察再次核对。作者、时长或链接不可见时返回 `null`；不会猜链接、补作者或把模型解释写成页面事实。字段关联不明确、标题重复、证据变化或条数不足会返回未完成/需接手。

结果位于 `summary.ui_results`，其中 `verified: true` 才表示已核验。`phone_task_status` 返回结果与状态供当前获授权会话使用。需要完成后主动回传时，要在任务范围中明确选择通知；定时任务还有独立的通知开关。

B 站模板要求搜索词和「综合」，并另外检查实际结果页特征与相关标题；不同版本不必都有「视频」标签。结果页满足条件后再独立读屏确认。搜索历史、联想列表、输入框原文和首页分类都不能冒充结果。

### 浏览与草稿

单应用浏览和非敏感设置仍可使用可见完成文字，例如显示设置页中的明确标签。可尝试将整段批准原文填入社交草稿，但发送/发布/评论、登录、支付、删除、安装、权限授予与含糊确认交人工接手。

任务可选择预定义直达入口 `entry_point`：默认 `app_home`，设置应用还可选择 `display_settings` 或 `wifi_settings`。这些入口只适用于 `com.android.settings`，审批和收藏都会保留所选入口；不能输入任意 Intent、URI、组件或 shell，进入页面后仍需读屏核验。

允许输入非空的自定义任务必须至少完成一次输入并在新观察中核对原文，才能结合页面条件完成；列表是可用原文范围，不代表每项都必须输入。空白、无标签或被判定敏感的编辑器仍可能需要人工，不能承诺任意 App 的草稿都可自动完成。

## 收藏、参数与经验复用

在任务记录「收藏为模板」保存已完成任务；服务端也接受实际批准过的任务范围。模板包含名称、应用、原目标、文字条件和可选参数。例如把源任务中的 `Kotlin` 声明为参数 `query`，保存后只需填写 `Android` 即可生成新提案。

参数只替换模板目标、允许输入和完成文字中的声明占位符，不能改包名、动作范围、设备绑定或步数上限。每次手动使用收藏仍生成独立待批准任务；选设备后再次核对完整范围。

只有任务事先选择 `remember_recipe` 且最终成功核验，才返回可保存的操作经验。经验保存控件特征、输入参数索引和步骤后的页面条件，不保存坐标、旧快照 ID 或可复用授权。下次每步重新匹配当前控件；不唯一、页面条件变化或经验不适用时交模型重新判断，未知写结果不会重放。

## 接手后继续

任务失败或需要人工处理时，先检查手机。0.11.0 提供「重新观察并继续」：创建关联原记录的**新运行、新审批和新 grant**，只使用剩余动作预算，从当前页面开始观察，不自动重新打开目标 App，不复制旧步骤。

前次输入、点击或网络响应不确定时，必须明确确认已经检查当前状态。已完成和主动取消的任务不能续跑；剩余预算用尽、设备用途变化或已有后续提案时也不能再次沿用原记录。原任务和后续任务分别保留。

取消阻止服务端继续下发后续步骤；已发送到手机的动作可能仍完成。服务器会在在途请求退出前继续占用该设备，避免新任务与旧请求撞车。

## Bot 自主日程

先开启 `enable_task_routines`，从收藏中选择「设为日程」。逐项核对设备、实例化参数、模板范围、当地时间/时区、到期时间、总次数、每日次数与模型调用额度，然后明确批准。

- 只运行在已分配 `bot` 的设备；个人主力机不会接收日程任务。
- 每个日程最多 4 个每日时刻；执行只认当前当地分钟，离线、锁屏、过期心跳、Shizuku 未就绪或设备忙时不会补跑旧时刻。
- 同一本地日期/时刻最多运行一次，夏令时重复小时也不重复；跳过的夏令时时刻不补跑。
- 授权最长 90 天，总运行次数最多 1000，每日最多 4 次。App 默认提供更简洁的每日一次流程。
- 模型额度是**调用次数**，不是 Token 或金额。服务端在开始前预留该次额度，失败或重启不退还；它包含动作决策、结果提取和视觉辅助调用。
- 暂停、删除、更新日程或改变设备用途，会在后续动作检查中撤销旧授权。重新启用需要重新核对完整范围并批准。
- 默认为静默。通知必须另行勾选，只能发到服务器已记录的获授权私聊；可选择只在核验结果变化时通知。JSON 不能指定任意收件人。

日程在磁盘中先占用当次时刻和预算再发起任务。插件重启不会重放已预留或已启动的运行；失败通知也不自动反复发送。具体执行仍受相同应用范围、动作核验和敏感步骤规则约束。

## 截图与本地 OCR 辅助

需要 `enable_ui_vision=true`、App 0.5.0+、可看图模型，以及此次任务的 `allow_vision=true`。手机端对应截图/视觉操作也须按权限设置确认。普通任务不会因遇到困难就擅自开启截图。

优先使用可访问界面树。需要辅助理解时给模型截图与已有语义节点；节点不可用时可使用手机本地 OCR 文字节点。模型仍选择给定节点 ID，不能输出任意点击坐标。OCR 操作只允许点击或返回；执行前重新截屏比对，画面改变或目标不可靠则停止。

截图会发送到用户配置的视觉模型。结果提取仍需页面证据引用和新观察确认，截图/OCR 不能绕过密码、支付、系统权限或跨应用限制。游戏、自绘控件、动画和 OCR 尚未就绪时仍可能无法完成；首次 OCR 组件准备也可能需要网络。

## 个人版健康与设备自检

个人版保持简洁首页，健康是显式开启的独立链路。状态区区分当前来源、最近同步尝试、最近成功上传和错误原因；失败尝试不伪装成成功上传。超过 3 小时的服务器快照会提示过期，数据所属日期也须单独核对。

先打开来源健康 App 同步，再在 Phone Control 手动同步摘要。支持对接可接入 Health Connect 的健康 App；小米运动健康国区默认隐藏了，需要的可自行探索。实际可读类别取决于来源 App 的写入，Bot 版不读取健康。

连接自检按服务器响应、注册、心跳、Shizuku、输入法/本机授权和凭据状态定位问题。配对设备显示专用凭据与撤销状态；传统配置仍需区分面板 JWT、手机命令 Token 和 Relay Token。自检成功只代表对应检查项通过，不等于任意 UI 任务都兼容。

## 数据与接口摘要

模型收到任务范围、批准文字及本次操作的页面内容。开启截图辅助会额外发送截图；页面内容作为数据处理，不能扩大授权。任务历史保留批准范围、状态与用户请求的已核验结果；原始屏幕树、截图和模型原始回复不作为任务历史持续保存。外部模型服务可能有自己的请求记录策略。

| 接口 | 用途 |
| --- | --- |
| `POST /app/ui-task/propose` | 创建完整范围提案 |
| `POST /app/task/approve` / `cancel` | 批准或停止；启动响应不等于完成 |
| `POST /app/task/resume` | 从当前页面生成新的续跑提案 |
| `GET/POST /app/routines` | 收藏、删除、批准或暂停日程 |
| `POST /app/routines/propose` | 将模板参数化后创建新提案 |
| `GET/POST /app/pairing` | 面板生成一次性配对信息、查看设备 |
| `POST /app/pairing/revoke` | 面板撤销单台已配对设备 |
| `GET /app/diagnostics` | 设备状态诊断 |

UI 任务总开关、动作范围、配对凭据与日程授权在执行中持续检查。新功能是有限、可核验的尝试，不保证任意 App 自动操作、无条件续跑或跨 App 长流程。
